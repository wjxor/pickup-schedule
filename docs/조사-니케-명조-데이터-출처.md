# 조사: 니케 · 명조 데이터 출처

두 게임은 처음에 "공개 API가 없어 공지 페이지를 크롤링해야 하는 게임"으로 분류돼 있었다.
실제로 확인해 보니 **둘 다 JSON API가 있었다.** 화면 HTML을 긁을 필요가 없고,
본문에서 기간을 뽑는 작업도 정규식으로 끝난다. LLM 파서는 필요 없었다.

기록을 남기는 이유는 두 가지다. 하나는 엔드포인트와 파라미터를 어떻게 알아냈는지
남겨야 나중에 응답이 바뀌었을 때 같은 길을 다시 걸을 수 있기 때문이고,
다른 하나는 "크롤링해야 한다"는 최초 판단이 틀렸던 이유를 남기기 위해서다.

## 먼저 확인한 것

| 사이트 | robots.txt | 결과 |
|---|---|---|
| `nikke-kr.com` | 없음 (404) | 제한 선언 없음 |
| `wutheringwaves.kurogames.com` | `User-agent: *` (Disallow 없음) | 전체 허용 |

두 사이트 모두 수집을 막고 있지 않다. 그래도 요청 간격은 둔다.

## 명조: 워더링 웨이브

### 결론

공식 사이트가 **CDN에 올려둔 정적 JSON**을 읽어 화면을 그린다. 그 JSON을 그대로 쓴다.

```
목록  https://hw-media-cdn-mingchao.kurogame.com/akiwebsite/website2.0/json/G152/kr/ArticleMenu.json
본문  https://hw-media-cdn-mingchao.kurogame.com/akiwebsite/website2.0/json/G152/kr/article/{articleId}.json
```

인증도 헤더도 필요 없다. 목록 한 번이면 서비스 시작부터의 공지 378건이 전부 온다.

### 찾은 과정

1. `wutheringwaves.kurogames.com/kr/` 은 출시 전 사전예약 페이지였다. 실제 공지는 `/kr/main` 아래에 있다.
2. `/kr/main` 이 불러오는 번들(`static4.0/assets/index-*.js`)에서 `ArticleMenu.json` 과
   `` `${apiPrefix}/article/${t}.json` `` 을 찾았다.
3. `apiPrefix` 는 빌드 시점에 박히는 환경변수였다.

   ```js
   VITE_APP_JSON_PATH: "https://hw-media-cdn-mingchao.kurogame.com/akiwebsite/website2.0/json/G152/"
   apiPrefix = VITE_APP_JSON_PATH + window.__CURRENTLOCALE__   // 한국은 "kr"
   ```

### 함정

- **목록의 `articleContent` 는 20자로 잘린 미리보기다.** 기간을 뽑으려면 본문을 따로 받아야 한다.
- **같은 기간이 두 줄로 적힌다.** `(서버 시간)`(UTC+8)과 `(한국 시간)`(UTC+9)이 나란히 나온다.
  줄에 붙은 표기를 그대로 따르면 어느 쪽을 읽든 가리키는 순간은 같다. `(UTC+8)` 형태도 쓰인다.
- **버전 공지의 `점검 시간` 에는 타임존 표기가 없다.** 이 값이 중요한 이유는 아래에 있다.

### 상대 표현 치환

픽업 공지 중 상당수가 시작을 절대 시각으로 적지 않는다.

```
3.5 버전 업데이트 이후 ~ 2026년 7월 30일 10:59 (한국 시간)
```

버전 공지의 **점검이 끝나는 시각**이 곧 새 버전이 열리는 시각이므로, 그것을 버전 시작으로 쓴다.
점검 *시작* 을 쓰면 몇 시간 앞당겨진다.

```
✦점검 시간: 2026년 7월 10일 05:00 ~ 2026년 7월 10일 12:00
                                        └── 3.5 버전 시작
```

검증: 3.5 1차 픽업이 `07/30 10:59` 에 끝나고 2차 픽업이 `07/30 11:00` 에 시작한다. 정확히 맞물린다.

> **미해결**: `점검 시간` 줄에는 타임존이 적혀 있지 않다. 한국 사이트의 다른 무표기 시각이
> 모두 한국시간이므로 한국시간으로 해석했으나, 서버시간(UTC+8)일 가능성을 배제할 근거는 찾지 못했다.
> 어느 쪽이든 **오차는 최대 1시간이고 날짜는 어긋나지 않는다.** 수집 시 경고를 남긴다.

## 승리의 여신: 니케

### 결론

레벨 인피니트의 CMS API를 쓴다. **서명은 필요 없고 헤더 네 개면 된다.**

```
목록  POST https://na-community.playerinfinite.com/api/gpts.information_feeds_svr.InformationFeedsSvr/GetContentByLabel
본문  POST https://na-community.playerinfinite.com/api/gpts.information_feeds_svr.InformationFeedsSvr/GetContentInfoById
```

```
X-GameId: 16       X-AreaId: na
X-Source: pc_web   X-Language: ko
```

```json
{ "gameid": "16", "language": ["ko"], "offset": 0, "get_num": 10,
  "ext_info_type_list": [0, 1, 2],
  "primary_label_id": 309, "secondary_label_id": 892, "content_class": 0 }
```

`get_num` 은 10을 넘겨도 10건만 온다. 더 받으려면 `offset` 을 넘겨가며 요청한다.

### 찾은 과정

1. 사이트가 `sg-gpts.playerinfinite.com/comm/assets/lib/cmssdk.min.js` 를 불러온다.
   그 안에 엔드포인트 목록이 상수로 들어 있다.
2. SDK 초기화 값은 사이트 번들(`assets/aix-*.js`)에 있다.

   ```js
   Cmssdk.initSdks({ cms_config: {
     cms_gameid: "16", cms_areaid: "na", cms_lang: "ko", source_type: "pc_web",
     custom_cms_url: "https://na-community.playerinfinite.com",
   }})
   ```
3. 컬럼 ID(`primary_label_id` / `secondary_label_id`)는 `GetContentLabelList` 로 조회하는데
   **이 엔드포인트는 서명이 필요하다.** 서명을 흉내 내는 대신, 사이트를 브라우저로 열고
   페이지에 이미 로드된 SDK로 한 번만 조회해 값을 확인했다.

   | 컬럼 | `raw_label_name` | ID |
   |---|---|---|
   | 상위 | `official_news` | 309 |
   | 하위 | `NOTICE` (공지사항) | 892 |
   | 하위 | `NEWS` | 496 |

   값은 바뀌지 않으므로 설정에 적어 두고, 실제 수집은 서명이 필요 없는 목록 API만 쓴다.

### 함정

**공지 하나에 일정이 수십 개 들어 있다.** 다른 게임은 픽업 하나에 공지 하나를 쓰지만,
니케는 "8월 13일 업데이트 공지" 한 건에 신규 캐릭터 모집·이벤트·상점을 전부 묶는다.
공지 20건에서 일정 112건이 나온다.

다행히 본문이 번호 제목으로 일관되게 나뉘어 있다.

```
업데이트 주요 내용:
1. 신규 캐릭터
1.1 SSR 캐릭터 [퀸(니지마 마코토)]
    ...
    *기간 한정 모집 기간: 2026년 8월 13일 서버 점검 종료 이후 ~ 2026년 9월 10일 4:59:59 (UTC+9)
1.2 SSR 캐릭터 [아마기 유키코]
    *기간 한정 모집 기간: 2026년 8월 20일 5:00:00 ~ 2026년 9월 10일 4:59:59 (UTC+9)
```

이 번호를 경계로 쪼갠 뒤 구획마다 기간을 찾는다. 그래서 이 어댑터만
"공지 → 이벤트 여러 개"로 펼치는 단계를 갖는다.

**가챠 명칭이 세 가지다.** 하나만 알고 있으면 픽업의 절반을 놓친다.

```
*기간 한정 모집 기간:        *특수 모집 기간:        *기간 한정 선택 모집 기간:
```

**분류 근거는 기간 라벨 줄로 좁혀야 한다.** 본문 전체를 넣으면
"현재 픽업 중인 캐릭터를 체험할 수 있습니다" 같은 설명 문장 때문에
체험 기능이 픽업으로 뒤집힌다. 라벨 줄은 그 구획이 무엇에 대한 기간인지를 정확히 말해 준다.

**본문에 `<img>` 가 없다.** 구획별 이미지가 존재하지 않으므로,
공지 대표 배너를 물려주면 한 공지에서 나온 카드가 전부 같은 그림이 된다.
같은 배너를 여러 장 늘어놓느니 제목과 기간만 보여주는 편이 읽기 쉽다.

### 담는 범위

기간이 있는 구획을 전부 담으면 니케 혼자 전체의 38%를 차지하고,
그중 상당수가 '아레나 시즌', '상점 판매 기간', '로그인 보상' 같은 게임 내 운영 일정이다.
`keepTypes` 로 픽업 · 복각 · 이벤트 · 콜라보만 담는다. (112건 → 44건)

## 기간 표기 정리

두 게임이 쓰는 표기를 한자리에 모으면 이렇다. 뼈대는 `YYYY년 M월 D일 H:MM[:SS]` 로 같아,
정규식 조각과 변환 함수를 [`src/lib/collectors/korean-date.ts`](../src/lib/collectors/korean-date.ts) 에 모아 두 어댑터가 함께 쓴다.

| 표기 | 예 | 처리 |
|---|---|---|
| 절대 | `2026년 8월 20일 5:00:00 ~ 2026년 9월 10일 4:59:59` | 그대로 |
| 점검 후 → 절대 | `2026년 8월 13일 서버 점검 종료 이후 ~ 2026년 9월 10일 4:59:59` | 시작은 그날 0시 |
| 버전 상대 | `3.5 버전 업데이트 이후 ~ 2026년 7월 30일 10:59` | 버전 기간표로 치환 |
| 날짜만 | `2026년 4월 23일 ~ 2026년 5월 21일` | 0시 ~ 23:59:59 |
| 시작만 | `오픈 시간: 2026년 8월 13일` | 종료는 null |

`~` 는 반각(`~`) · 물결 대시(`〜`) · 전각(`～`)이 섞여 쓰인다. 전부 받아준다.

시각이 적혀 있지 않은 표기는 **시각을 지어내지 않고** 하루의 시작이나 끝으로 둔다.
그러면 시각은 최대 반나절 이르거나 늦을 수 있어도 **날짜는 절대 어긋나지 않는다.**
달력이 보여주는 것은 날짜이므로 이 정도 오차는 표시에 영향을 주지 않는다.

## 알아 둘 것

- 명조 3.6 배너 공지는 2026-08-22 기준 CDN에 아직 없다. 버전 공지(5358)에는 이벤트 목록만 있고
  픽업 기간이 없다. 버전 공지를 구획으로 쪼개 담을 수도 있지만, 나중에 개별 공지가 올라오면
  같은 일정이 두 번 들어간다. 그래서 하지 않는다. 자동 수집이 하루 4번 도므로 올라오면 들어온다.
- 두 API 모두 문서화된 공개 API가 아니다. 예고 없이 바뀔 수 있으므로,
  어댑터는 응답 형식이 어긋나면 예외를 던지지 않고 `skippedReason` 으로 보고한다.
