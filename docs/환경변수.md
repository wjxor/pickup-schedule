# 환경변수 설정

## 왜 필요한가

데이터베이스 주소나 API 키 같은 비밀값을 소스 코드에 직접 적으면, GitHub에 올리는 순간 그대로 유출된다.
그래서 이런 값은 `.env.local` 파일에 따로 넣고, 이 파일은 `.gitignore`에 걸어 git 추적에서 제외한다.

## 설정 방법

프로젝트 루트에 `.env.local` 파일을 만들고 아래 내용을 붙여넣은 뒤 값을 채운다.

```bash
touch .env.local
```

```dotenv
# ------------------------------------------------------------
# Supabase — 대시보드 > Project Settings > API 에서 확인
# ------------------------------------------------------------

# 프로젝트 URL. NEXT_PUBLIC_ 접두사가 붙으면 브라우저에도 그대로 노출된다.
NEXT_PUBLIC_SUPABASE_URL=

# anon(공개) 키. 노출을 전제로 만들어진 키이며, RLS 정책상 읽기만 가능하다.
NEXT_PUBLIC_SUPABASE_ANON_KEY=

# service_role 키. RLS를 우회하는 전권 키라 절대 브라우저로 나가면 안 된다.
# 수집기·관리자 API 같은 서버 코드에서만 쓴다.
SUPABASE_SERVICE_ROLE_KEY=

# ------------------------------------------------------------
# 수집기
# ------------------------------------------------------------

# 공지 본문에서 날짜를 뽑아내는 LLM 파서용 키.
# 비워두면 파서가 비활성화되고, 해당 게임 수집은 건너뛴다.
ANTHROPIC_API_KEY=

# 수집기가 외부 API를 호출할 때 쓰는 User-Agent.
# 어디서 온 요청인지 밝히는 것이 크롤링 예절이다.
COLLECTOR_USER_AGENT="PickupScheduleBot/0.1 (+https://example.com/about)"
```

## 키 3종의 차이

| 키 | 노출돼도 되나 | 쓰는 곳 | 권한 |
|---|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | ✅ 공개 전제 | 브라우저 + 서버 | 주소일 뿐 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ✅ 공개 전제 | 브라우저 + 서버 | RLS 정책이 허용한 범위(현재는 읽기만) |
| `SUPABASE_SERVICE_ROLE_KEY` | ❌ **절대 금지** | 서버 코드만 | 모든 테이블 읽기·쓰기·삭제 |

`NEXT_PUBLIC_` 접두사는 Next.js의 규칙이다. 이 접두사가 붙은 값만 브라우저 번들에 포함되고,
붙지 않은 값은 서버에서만 읽힌다. 그래서 `SUPABASE_SERVICE_ROLE_KEY`에는 절대 접두사를 붙이면 안 된다.

## 값이 없을 때의 동작

아직 Supabase 프로젝트를 만들지 않았어도 개발은 진행할 수 있다.
환경변수가 비어 있으면 앱은 `src/mocks/`의 목 데이터로 동작한다. (`src/lib/events/repository.ts` 참고)
