# 배포 (Vercel)

GitHub 저장소를 Vercel에 연결하면 `main` 에 푸시할 때마다 자동으로 배포된다.

## 왜 Vercel인가

Next.js를 만든 회사의 플랫폼이라 별도 설정 없이 App Router, ISR(주기적 재생성),
이미지 최적화가 그대로 동작한다. 개인 프로젝트 규모에서는 무료(Hobby)로 충분하다.

---

## 1단계 — 프로젝트 연결

1. [vercel.com](https://vercel.com) 에 **GitHub 계정으로 로그인**한다.
2. **Add New...** → **Project**
3. **Import Git Repository** 목록에서 `wjxor/pickup-schedule` 을 고른다.
   목록에 없으면 **Adjust GitHub App Permissions** 로 저장소 접근을 허용한다.
4. 빌드 설정은 **건드리지 않는다.** Vercel이 Next.js를 자동 인식한다.

   | 항목 | 자동 감지값 |
   |---|---|
   | Framework Preset | Next.js |
   | Build Command | `next build` |
   | Install Command | `npm ci` |
   | Output Directory | (자동) |

## 2단계 — 환경변수 등록

**Deploy 를 누르기 전에** Environment Variables 를 펼쳐 두 개를 넣는다.

| Name | 값 | 왜 필요한가 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | `.env.local` 의 같은 값 | 화면이 DB에서 일정을 읽는다 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `.env.local` 의 같은 값 | 위와 동일. RLS 정책상 읽기만 가능하다 |

> **`SUPABASE_SERVICE_ROLE_KEY` 는 넣지 않는다.**
> 웹 앱은 데이터를 읽기만 하므로 필요가 없다. 전권 키를 배포 환경에 두면 노출 경로만 늘어난다.
> 이 키는 수집기에서만 쓰며, 이미 GitHub Actions Secrets 에 등록돼 있다.

빠뜨리면 어떻게 되는가: 빌드는 성공하지만 사이트가 목 데이터로 뜨고
화면 상단에 "데이터베이스가 연결되지 않아..." 안내가 보인다. 그때 환경변수를 채우고
**Redeploy** 하면 된다.

## 3단계 — 배포

**Deploy** 를 누르면 1~2분 뒤 주소가 나온다.

> **주소를 추측하지 말 것.**
> `*.vercel.app` 서브도메인은 전 세계에서 하나뿐이라 먼저 차지한 프로젝트가 가져간다.
> `pickup-schedule.vercel.app` 은 이미 무관한 다른 서비스가 쓰고 있어서,
> 이 프로젝트에는 뒤에 식별자가 붙은 다른 주소가 배정된다.
> (예: `pickup-schedule-wjxor.vercel.app`)
>
> 실제 주소는 아래 중 아무 데서나 확인한다.
> - 배포 완료 화면의 **Visit** 버튼
> - [vercel.com/dashboard](https://vercel.com/dashboard) → 프로젝트 → 상단 표시
> - 프로젝트 → **Settings** → **Domains**

접속해서 확인할 것:

- 상단에 "목 데이터로 동작 중" 안내가 **없어야** 한다. 있으면 환경변수 문제다.
- 일정 카드가 보이고, 상단 "일정표" 탭에서 간트 차트로 전환된다.
- 카드의 "원문" 링크가 각 게임 공식 공지로 연결된다.

---

## 이후 배포

`main` 에 푸시하면 자동으로 다시 배포된다. 따로 할 일이 없다.

기능 브랜치에 푸시하면 **미리보기 배포(Preview)** 가 별도 주소로 만들어진다.
`main` 에 합치기 전에 실제 환경에서 확인할 수 있다.

## 주소를 바꾸고 싶다면

배정된 주소가 마음에 들지 않으면 프로젝트 → **Settings** → **Domains** 에서
`원하는이름.vercel.app` 을 추가할 수 있다. 비어 있는 이름이면 바로 붙는다.

프로젝트 이름 자체를 바꾸는 방법(**Settings** → **General** → Project Name)도 있지만,
기본 주소가 따라 바뀌므로 기존 링크를 공유한 뒤라면 주의한다.

## 리전 설정

[`vercel.json`](../vercel.json) 에서 `icn1`(서울)로 지정해 두었다.

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "regions": ["icn1"]
}
```

한국 사용자 대상 서비스이므로 함수가 실행되는 위치를 가깝게 둔다.
정적 파일은 이 설정과 무관하게 전 세계 CDN에 배포된다.

Hobby 플랜은 리전을 하나만 지정할 수 있다. 여러 개를 적으면 빌드가 실패한다.

## 데이터가 갱신되는 방식

```
GitHub Actions (하루 4번)  →  Supabase
                                  ↓  5분마다 재생성
                            Vercel (ISR)  →  방문자
```

메인 페이지는 `revalidate = 300` 으로 5분마다 다시 만들어진다.
매 요청마다 DB를 조회하지 않으므로 방문자가 늘어도 DB 부하가 커지지 않는다.

수집 직후 화면에 바로 반영되길 원하면 Vercel 대시보드에서 **Redeploy** 하거나,
`revalidate` 값을 줄이면 된다.

## 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 빌드 실패 | 대개 타입 오류 | 로컬에서 `npm run build` 로 재현 |
| "목 데이터로 동작 중" 표시 | 환경변수 누락 또는 오타 | Settings → Environment Variables 확인 후 Redeploy |
| 일정이 오래됨 | 수집이 안 돌고 있음 | GitHub Actions 탭에서 워크플로 실행 이력 확인 |
| 빌드가 리전 오류로 실패 | Hobby 플랜에 리전 2개 이상 지정 | `vercel.json` 의 `regions` 를 하나만 남긴다 |
